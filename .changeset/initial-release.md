"@hussmartinez/ai-core": minor
---

First release of `@hussmartinez/ai-core`, the `@hussmartinez` family's AI provider layer. It has adapters for Anthropic, Gemini and OpenAI-compatible APIs, with a Kimi preset, plus a server request handler and a browser transport that talks only to it. It's the family's only package with network code. It makes requests only through adapters and transports your application creates, to the endpoints you configure, and API keys stay on your server by default.

- **Package shape:** an ES module package with one entry per part, so you bundle only what you use:
  - the core and browser transport, `@hussmartinez/ai-core`;
  - the request handler, `@hussmartinez/ai-core/server`;
  - one entry per provider: `/anthropic`, `/gemini` and `/openai-compatible`;
  - a contract-test suite for custom providers, `@hussmartinez/ai-core/testing`.
- **No request on import:** no entry makes a network request when it's imported, in browsers or on servers.
- **Errors:** `AiError` extends sdk-core's `SdkError`, with stable codes (`AiErrorCode`) and `isAiError(error, code?)`, which recognises errors from any copy of the package or rebuilt from the wire. Show users `aiCoreMessages`' text for the code, never `error.message`.
- **Limits:** `responseLimits` (`responseBytes` 16 MB, `streamDuration` 15 minutes, `idleTime` 2 minutes) for adapters and the transport, and `requestLimits` (`requestBytes` 8 MB) for the request handler. Each has its own error code. Hosts override them with `{ maximum, warning }`, and unknown names throw.
- **Messages:** `aiCoreMessages`, the English catalogue with text for every error code and limit warning, for `createMessages` from `@hussmartinez/sdk-core`.
- **The message model and the provider shape:** `AiMessage` with `text`, `image` (bytes only), `tool-call`, `tool-result` and opaque `provider-state` parts, and `AiProvider` with `complete()` and `stream()`, which SDK ports match structurally without importing ai-core.
- **Testing:** `@hussmartinez/ai-core/testing` has `defineProviderContract(makeProvider, { describe, it })`, the suite every provider passes, which works with Vitest, Jest or `node:test`, and `createFakeProvider(turns)`, a scripted provider with no network for your own tests, which records the requests it receives.
- **Provider errors:** failures from a provider have their own codes, such as `PROVIDER_RATE_LIMITED`, `PROVIDER_OVERLOADED`, `PROVIDER_AUTHENTICATION` and `NETWORK_ERROR`. Each says in `details.retryable` whether the same call can succeed later, and gives `details.retryAfter` in seconds when the provider sent one. ai-core never retries on its own.
- **Keys in browsers:** an adapter that holds an API key refuses to run outside a recognised server runtime (Node, Bun, Deno, Vercel Edge or Cloudflare Workers), including in pages and browser workers, with `BROWSER_KEY_REFUSED`, unless you pass `dangerouslyAllowBrowser: true`.
- **Anthropic:** `createAnthropic({ apiKey, model })` from `@hussmartinez/ai-core/anthropic` calls the Claude Messages API (version `2026-10-21`). It streams every call and replays thinking blocks unchanged as `provider-state`. It maps stop reasons, usage (including cache and thinking tokens) and errors, with `SPEND_LIMIT_REACHED` for a spend-capped account. `apiKey` can be a function, read on every request. Options include `maxOutputTokens` (default 16,000), `baseURL`, `fetch`, `limits` and `onWarning`.
- **OpenAI-compatible APIs and Kimi:** `createOpenAICompatible({ apiKey, baseURL, model, provider })` from `@hussmartinez/ai-core/openai-compatible` calls any Chat Completions API (OpenAI's, a gateway's, or a local server's) with streaming and usage, and `createKimi({ apiKey, model })` sets Kimi's base URL (`https://api.moonshot.ai/v1`). A thinking model's `reasoning_content` is kept as `provider-state` and sent back as-is, as Kimi requires. `maxTokensField` chooses `max_completion_tokens` (the default) or `max_tokens`. It always sends `store: false`, so the provider keeps no copy of the conversation (ADR 0008). `sendStore: false` leaves the field out for APIs that reject it, and the Kimi preset leaves it out because Kimi doesn't document it. `providerOptions` can never ask for storage.
- **Gemini:** `createGemini({ apiKey, model })` from `@hussmartinez/ai-core/gemini` uses Google's Interactions API statelessly. It sends the full history with every call and always sets `store: false`, so Google keeps no copy of the conversation (ADR 0008). Thought steps, with their signatures, are kept as `provider-state` and sent back unchanged, and function calls keep Gemini's own IDs. The key goes in the `x-goog-api-key` header, never in a URL.
- **Request handler:** `createAiHandler({ provider, prepare })` from `@hussmartinez/ai-core/server` is the endpoint the browser transport calls, as a `(request: Request) => Promise<Response>` for Next.js route handlers, Hono, Node, Deno, Bun and Workers. `prepare` is required: it authenticates and rate-limits each request, and returns a `Response` to reject it or the call's settings (`AiCallSettings`), with a required `maxOutputTokens`. The browser sends only `{ protocol: "ai-core/1", messages }`, and any other field is rejected. The handler accepts only `POST` with `content-type: application/json`, within `requestBytes`, from `allowedOrigins` when you set them, with `onWarning` before `requestBytes` is reached. It never logs or adds CORS headers. It streams the `ai-core/1` protocol as server-sent events. Changing the system prompt or tools during a conversation fails fast with 409 `CONTEXT_CHANGED`, detected with a SHA-256 of their RFC 8785 canonical JSON, so a handler in another language can compute the same hash, and `withoutProviderState(messages)` lets a conversation continue without its earlier reasoning.
- **Browser transport:** `httpTransport({ url })` from `@hussmartinez/ai-core` is the page's provider. It calls your `createAiHandler` endpoint, such as `/api/chat`, over `ai-core/1`. It holds no key, so it runs in pages and workers, and it sends only the conversation: setting `model`, `system`, `tools` or any other server-side field fails with `INVALID_REQUEST` before anything is sent. Optional `headers` (an object, or a function called for each request) carry your own session credentials, never a provider key. The handler's errors arrive as the same `AiError`s, such as `CONTEXT_CHANGED`, and the response limits protect the page from a misbehaving server too.
- **Contract suite for relays:** `defineProviderContract(make, { describe, it }, { relaysState: true })` tests a provider that passes on another provider's state, such as the transport.
- **Portable formats (sdk-core ADR 0045):** the `ai-core/1` protocol's JSON Schema ships with the package, as `@hussmartinez/ai-core/formats/hm-ai-protocol/v1.schema.json`, and `docs/formats/` describes it and the context hash. Every refusal of a request or a stream carries a stable `details.reason`, such as `unknown-field` or `invalid-base64`, beside its code.
